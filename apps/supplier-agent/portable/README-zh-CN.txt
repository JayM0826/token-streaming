共算云供应客户端（Windows x64 便携版）

1. 解压整个文件夹，不要只单独复制启动脚本。
2. 双击 start-agent.cmd。
3. 默认浏览器会打开本地供应控制中心。
4. 首次配置 Provider、精确模型、共算云平台地址、稳定公网 HTTPS 节点地址、API Key 和本地加密口令。
5. 客户端会自动生成网关令牌；只把“平台接入资料”中的网关地址和网关令牌提交到共算云。
6. 文件任务默认支持到 256 MiB，并由客户端主动连接平台领取；界面会显示任务编号、分段和已处理字节。无需为文件任务开放新端口。

安全要求：
- 不要填写 ChatGPT/Codex 密码、Cookie 或 OAuth 登录态。
- 不要把本地管理端口 8790 暴露到公网或局域网。
- 客户端只在自动打开地址的 URL fragment 中携带一次性启动凭据；fragment 不进入 HTTP 请求或 Referer，页面立即从历史记录擦除它并 POST 换取 HttpOnly、SameSite=Strict Cookie。不要复制、收藏或记录启动地址。
- 网关令牌每次查看都要重新输入本地口令，并在 60 秒后自动隐藏。
- 公网反向代理或命名隧道只转发节点端口（默认 8789）。
- 当前文件任务只处理 UTF-8 文本、Markdown、CSV/TSV、JSON/NDJSON 和 XML；不解压、不执行文件，也不访问文件中的链接。
- 文件任务使用 v2 加密断点，只保存中间摘要；版本、任务编号、创建和过期时间都进入 AES-GCM 附加认证数据。默认及最大生命周期为固定 6 小时，更新断点不会顺延到期时间。
- 只有本地已认证断点的任务编号及已完成段数与平台指定恢复段完全一致时才会续跑；`resume_from_segment > 0` 却没有完全匹配断点时，会在下载客户文件或调用 Provider 前以不可重试的 ARTIFACT_CHECKPOINT_REQUIRED 终止。平台以第 0 段开始新 attempt 时，客户端会先删除同任务旧断点，并明确不把旧状态交给执行内核；新 attempt 首次写入断点时重新获得固定 6 小时生命周期。
- 客户端启动后的首次轮询及每次后续轮询都会先做有界清扫，删除过期、旧版 v1、损坏和遗留临时断点；只要发现任何无法删除的不安全文件，就以不可重试的 CHECKPOINT_CLEANUP_FAILED 阻止新 claim。当前任务断点在读取时无法安全删除也使用同一错误拒绝继续。平台已经接受终态完成后若本地断点删除失败，客户端不会再向平台误报任务失败，而是返回 CHECKPOINT_CLEANUP_FAILED，并在当前进程记入待删除集合；所有其他不可重试终态也通过同一条路径删除断点，删除失败同样进入待删除集合。后续每次 claim 前都会重试，删除成功前不领取新任务。该集合不跨进程保存；重启后断点中经过认证且不顺延的到期时间仍把可恢复有效期限制为最多 6 小时，过期后的 claim 前清扫若仍无法物理删除也会阻止领取。原始客户文件不写入普通本地目录。
- 供应节点和上游 Provider 在执行时仍会看到客户明文；这不是“供应方不可见”的机密计算环境。
- Provider API Key 只在本机加密保存，绝不能提交给平台。
- v2 密钥库使用整个规范化配置的摘要作为 AES-GCM 附加认证数据；手工修改上游地址、白名单、模型、限制或其他 profile 字段都会导致解锁失败。
- 已存在的配置不会被首次设置覆盖。旧版 v1 密钥库不做原地迁移：先确保节点下线且没有活动文件任务，用 doctor.cmd 记录配置路径并把整个状态目录移到私密备份，再撤销并轮换旧 Provider Key 与网关令牌，然后重新完成首次设置。
- 忘记本地加密口令无法恢复，需要轮换 Provider Key 和网关令牌。

doctor.cmd 可以在不解锁凭据的情况下检查本地配置。
