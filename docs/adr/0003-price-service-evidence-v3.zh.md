# ADR 0003：网关 v3 价服一致执行凭证

- 状态：接受
- 日期：2026-08-25
- 取代：ADR 0001 的推理响应协议部分

## 背景

批准时证明只能说明某个节点在审核时声明了哪些 Provider、模型和容量，不能证明某一笔已计费任务实际使用了订单购买的服务。若结算只相信供应方自行填写的模型名和 token 数，供应方就可能用更便宜的模型替代，或夸大用量，形成“以次充好”。

## 决策

供应网关升级为 `gongsuanyun.gateway.v3`，推理端点为 `/v3/inference`，证明端点为 `/v3/attestation`。每个成功推理响应必须包含 `gongsuanyun.execution-evidence.v1` 与 HMAC-SHA256 签名。规范化签名载荷依次绑定：

1. 凭证版本、平台任务 ID、Provider ID；
2. 订单购买的精确模型与上游响应返回的实际模型；
3. Provider 请求 ID、输入 SHA-256、输出 SHA-256；
4. 输入、输出、总 token 用量；
5. Provider 完成时间和可选回执引用。

供应节点的 Provider Adapter 必须读取上游响应中的实际 `model` 字段，并与订单精确模型比较；不一致时返回 `UPSTREAM_MODEL_MISMATCH`，不得生成成功响应。模型别名解析为不同快照时同样 fail closed，供应方应以实际上游返回的精确模型发布报价。

控制面只接受精确字段集合，重新计算输入和输出摘要，核对 Provider、购买模型、实际模型、任务 ID、用量、时间窗口和签名。全部通过后，控制面计算结算，并以一个 D1 原子批次写入完成任务、用量记录、不可变 `service_evidence`、买方扣款、供应方收入和平台费。任一验证失败返回稳定错误码 `SERVICE_EVIDENCE_FAILED`，任务标记失败，不写入任何财务分录。

浏览器只读取最小化的 `ServiceProofView`：保障等级、Provider、购买/实际模型、Provider 请求 ID、报价、实扣金额、证据摘要和完成时间。原始输入、输出摘要和签名不进入浏览器 DTO。

## 保障边界

当前等级 `node-signed-provider-response` 证明：持有网关共享密钥的官方节点代码观察到了相应上游响应字段，并且响应在传输或入库前未被替换。它不能阻止掌控服务器和密钥的恶意供应方修改节点代码，也不是上游 Provider 的独立签名证明。

因此商业策略应分层：当前等级只开放 P0/P1 和闭测额度；更高额度或敏感任务需使用 Provider 官方签名回执、平台托管 Provider 账户，或带远程证明和密钥释放策略的可信执行环境。

## 后果

- “没有可验证服务凭证，就没有扣款”成为机器可执行的不变量。
- 价格、实际服务、用量和财务分录可以按任务审计，历史不能被覆盖。
- v3 与 v2 不兼容；闭测尚无已批准真实节点，因此直接拒绝 v2，避免双协议降级面。
- HMAC 共享密钥仍需要加密存储、轮换和域名白名单；后续可把签名升级为节点非对称密钥与短期证书，而不改变领域验证语义。
