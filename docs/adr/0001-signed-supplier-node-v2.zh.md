# ADR 0001：签名供应节点协议 v2

> 当前状态：已被 ADR 0003 的网关 v3 取代；本文件保留为历史决策记录。

- 状态：接受
- 日期：2026-08-25

## 背景

闭测控制面已经能够保存加密网关令牌并调用供应方 HTTPS 地址，但 v1 只使用 Bearer Token，仓库也没有供个人或企业部署的真实节点。仅有 Bearer 身份无法把请求体、任务 ID 和时间窗口绑定在一起，也缺少统一的重放、容量与 Provider 边界。

## 决策

采用 `gongsuanyun.gateway.v2`：控制面发送 Bearer Token，并以同一高熵令牌作为 HMAC-SHA256 密钥，对时间戳、一次性 nonce、任务 ID 和精确 JSON 请求体 SHA-256 摘要签名。节点在解析业务内容前验证身份与签名，在五分钟窗口内拒绝 nonce 重放。

`apps/supplier-node` 作为独立、无界面的 Node.js 22 运行时，只依赖协议包。它绑定环回地址为默认值，公开部署位于 TLS 反向代理之后；只访问固定 HTTPS 上游地址且禁用重定向；只允许配置中的模型、P0/P1 数据等级和容量。Provider 原生请求、认证、用量和错误止于 Adapter。提示词与输出不写磁盘、不写日志，幂等重放仅在内存保留十五分钟。

控制面继续保存加密的节点共享令牌，但永不接收节点的上游 Provider API Key。客户推理不会经过开发者本地 Codex 会话。

## 后果

- v2 是对 v1 的破坏性协议升级；当前闭测尚无获批真实 v1 节点，因此控制面直接切换并拒绝旧版本。
- 同一令牌承担 Bearer 身份与 HMAC 密钥用途，部署时必须使用节点生成的至少 256 位随机值，并通过控制面的加密字段保存。
- 服务器节点所有者仍可能观察进程内明文，所以 P2/P3 不开放；更高等级需要出站代理与机密计算的独立协议。
- 真正公网启用仍要求供应商业务授权、生产域名白名单和外部合规审核，代码不会绕过这些闸门。
