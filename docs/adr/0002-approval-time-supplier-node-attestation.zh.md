# ADR 0002：批准时进行签名供应节点证明

- 状态：接受
- 日期：2026-08-25

## 背景

域名白名单和人工证据审核只能证明平台允许连接某个公网地址，不能证明该地址当前运行的是预期协议，也不能证明节点实际配置的 Provider、精确模型、数据等级和容量覆盖供应商申请。公开健康接口若直接返回完整库存，还会泄露不必要的供应侧信息。

## 决策

`GET /healthz` 只公开 `status` 与 `protocol_version`。管理员批准授权时，控制面使用已加密保存的网关令牌，对一次性 `request_id`、随机 challenge、时间戳、nonce 和精确请求体摘要进行 HMAC-SHA256 签名，并请求同源的 `POST /v3/attestation`。

供应节点先验证 Bearer、签名、时间窗口和 nonce，再回显 challenge，并返回当前 Provider、精确模型清单、P0/P1 数据等级和容量上限。领域层以严格结构校验验证响应：协议必须是 `gongsuanyun.gateway.v3`、节点必须 ready、请求与 challenge 必须匹配、申请的模型模式至少匹配一个精确模型，且申请的数据等级和各项容量均不能超过节点声明。任何连接、格式或范围不一致都禁止批准。

证明只决定节点配置是否覆盖申请，不替代 Provider 商业授权、KYC/KYB、税务、支付或人工合规审核。节点上游 API Key 始终只保留在供应服务器。

## 后果

- 被批准的授权与一个当时在线、持有共享令牌且配置匹配的节点绑定，减少错误配置和冒充风险。
- 完整节点库存不再通过匿名健康接口泄露。
- 管理员批准依赖节点在线、TLS 有效、域名在生产白名单中；暂时离线时批准会失败并可重试，不会写入部分批准状态。
- 当前证明不是硬件远程证明，不能阻止节点所有者修改进程或观察明文，因此 P2/P3 继续关闭。
