# Token Streaming

Token Streaming is a CLI-first agentic coding runtime for model orchestration, repository understanding, safe patching, test feedback, and event-sourced execution history.

The project is intentionally headless at the core layer. The CLI is the first host, and a desktop host can later reuse the same runtime contracts.

## V1 Scope

- Implement one real orchestration strategy: `default`.
- Keep product modes represented as `economy`, `max`, and `auto`.
- Treat `.ai/`, `module.yaml`, and `flow.yaml` as first-class repository context.
- Use local Codex exec by default, with explicit API routing for OpenAI, Anthropic, and Gemini and a stub fallback for offline development.
- Persist event logs, checkpoints, and markdown run reports.

## Compute Marketplace Extension

- Treat Token Streaming as the engineering scaffold and source of repository conventions, not as a requirement that customer inference use Codex.
- Use the local Codex project profile in `.codex/config.toml` for AI-assisted planning, implementation, review, and documentation.
- Keep customer inference provider-neutral behind versioned capacity offers and provider adapters; never send customer prompts to the developer's Codex session.
- Build the marketplace as a separate bounded context with protocol-first, headless domain modules and replaceable TUI, desktop, mobile, web, and API hosts.
- Treat individual and organization suppliers as first-class V1 participants under one authorization and metering contract, with KYC/KYB differences expressed as policy.
- Keep P2/P3 capacity fail-closed until dedicated retention, residency, and compliance policy is implemented in the protocol.
- The closed-beta Web deployment uses platform sign-in, D1-backed tenant state, buyer-only content views, explicit standard/strict privacy modes, active content purge, separately encrypted credentials/replayable content/files, keyed digest commitments, durable rate limits, and append-only usage/ledger records. Gateway credential AES and its independent Agent lookup HMAC use bounded keyrings with persisted key ids, legacy dual-read, signed-request lazy lookup migration, four-row CAS rewrap, D1 reference retirement gates, and persistent key-material canaries; Agent nonce claims span every readable lookup namespace atomically, and same-tenant administrators cannot approve their own authorization. Artifact purge atomically pairs a durable object-deletion queue row with the exact immutable generation's transition to `deleting` before R2 mutation, so a stale `ready` row cannot permanently suppress retry. Cleanup advances one artifact and four generations per invocation plus four due queue keys; incomplete explicit purge returns retryable 503, and `deleted` requires zero remaining generation rows. Full maintenance includes schema bootstrap and therefore has Workers Paid's 1,000 D1 queries-per-invocation quota as a hard production prerequisite despite the small cleanup transitions. Because task content_purged_at can mark output expiry alone, full task purge separately proves the task marker, instruction/output erasure, purged/deleted artifact state, and zero generations, leaving input purge reachable after result expiry. Any later explicit final-state retry idempotently backfills missing artifact/task completion audits without duplicate tenant/action/resource events. Maintenance monitors key rotation plus object deletes, unclaimed expired artifacts, and pending generation tombstones with separate 24-hour breach counts.
- Supplier authorization lifecycle supports command-bound pending withdrawal, active revocation, and live-attested write-only Gateway-token replacement. Every transition advances a storage revision; reserve/claim gates recheck authorization, offer, supplier and tenant relationships atomically. Revocation scrubs credential material and heartbeat state, disables the last supply path, fails unstarted work, and preserves only guarded in-flight completion or reservation-held leased cancellation.
- Gateway key custody supports per-key write-only Sites slots, a strict non-secret staged/readable manifest, domain/key-bound material verifiers, D1-persisted monotonic generation/hash state, globally unique lifecycle commands, explicit non-TOFU canary registration, and a verifier-bound fresh-database baseline that atomically consumes migration-proven one-way eligibility while complete durable history remains empty. The independently authenticated preflight stays D1-read-only and treats pre-upgrade lifecycle tables as unavailable rather than creating them. Removing an adopted manifest is also treated as rollback. The key recovery runbook still requires independent KMS/HSM custody and separates runtime retirement, Sites-copy deletion, and final recovery-copy destruction; slot delivery and canaries are not backups.
- The deployable supplier node implements the signed `gongsuanyun.gateway.v3` contract for personal and organization servers, with exact provider/model/data allowlists and replay journal v2 on a persistent state volume. `SupplierNodeConfig.replayJournalPath` must resolve to a non-empty durable path; startup fails instead of falling back to memory. Request bodies are represented only by gateway-token-keyed domain-separated HMAC commitments; live v1 records migrate at startup, claims are fsynced before execution, bounded compaction is atomic, and storage failure marks readiness plus later claims unavailable. The journal currently permits one active writer per gateway token; active-active HA requires a shared atomic replay-claim store rather than only shared filesystem state. The node also provides bounded in-memory result idempotency, restart-safe rejection, local capacity enforcement, no prompt/output logging, minimal public readiness, signed approval-time inventory attestation, and node-signed per-job execution evidence. The Web control plane settles only after exact Provider/model/content-digest/usage verification and writes evidence plus ledger postings atomically.
- The cross-platform Supplier Agent is a replaceable local GUI/TUI host over supplier-node. It encrypts Provider and gateway credentials at rest, authenticates vault v2 against a domain-separated digest of the complete canonical validated profile, and fails closed on unbound vault v1 pending credential rotation and fresh setup. It keeps management loopback-only, exchanges a one-time URL-fragment launch secret for an HttpOnly SameSite=Strict Cookie, refuses first-run setup overwrite, reauthenticates and throttles credential reveals, supports safe unlock/drain/lock, and never duplicates inference, signature, capacity, or provider-adapter logic.
- The consumer Web is installable as a PWA on supported desktop and mobile browsers. Native consumer shells remain optional hosts over the same marketplace API rather than a prerequisite for closed-beta use.
- Large text artifacts use a separate async data plane: resumable 4 MiB browser chunks, tenant-bound AES-256-GCM R2 storage with pending/ready/deleting coordination plus a 24-hour independent repeated-deletion tombstone, D1 metadata, short-lived outbound Agent capability heartbeats, 5-minute leases capped by a six-hour absolute deadline per attempt, and atomic Agent checkpoint-v2 envelopes with authenticated task/timestamps, a non-sliding six-hour maximum lifetime per attempt, exact platform-confirmed resume, zero-segment fresh-attempt reset without old runtime state, and bounded cleanup before every claim. A positive resume segment without an exact authenticated checkpoint fails with `ARTIFACT_CHECKPOINT_REQUIRED` before Provider execution. Any discovered unsafe checkpoint file that cannot be deleted blocks the claim. If checkpoint deletion fails after accepted completion or any non-retryable terminal failure, the current Agent process records pending cleanup, returns `CHECKPOINT_CLEANUP_FAILED`, and blocks later claims until deletion succeeds; after restart the authenticated fixed expiry preserves the six-hour validity bound and pre-claim cleanup fails closed on an undeletable expired file. Execution uses bounded map/reduce, aggregate exact-model evidence, cross-workload token-budget reservation, command-bound two-phase cancellation, and independently authenticated retention cleanup that validates distinct 256-bit key domains before mutation and exports deletion-retention breach metrics. `gongsuanyun.artifact.v1` treats `cancelling` as an additive non-terminal state, while the breaking Agent contract is isolated in `artifact-worker.v2`. The implemented limit is 256 MiB and binary/archive formats fail closed.
- Never describe shared execution as end-to-end confidential: the matched supplier and upstream Provider see plaintext. Strict mode minimizes retention and identifiers; supplier-invisible execution requires a customer node or remotely attested confidential-computing tier.
- Treat promotional beta balance as non-cash test credit; regulated payments, tax/KYC evidence custody, and payouts are external launch dependencies rather than simulated functionality.
