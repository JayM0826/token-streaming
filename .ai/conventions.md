# Conventions

- Use TypeScript with `NodeNext` modules.
- Keep package boundaries explicit and small.
- Prefer no external dependency when Node built-ins are enough.
- Use append-only events for execution history.
- Keep runtime core UI-agnostic.
- Represent future features with narrow interfaces before implementing full behavior.
- Model marketplace state transitions as versioned append-only events and keep personal/organization differences in explicit policy tables.
- Re-check current verification and authorization at every capacity publication; offers may narrow but never widen approved scope.
- Use command/causation IDs plus optimistic aggregate versions for idempotent marketplace writes.
- Serialize authorization review, withdrawal, revocation, and credential replacement by request/revision target, bind each client command to one tenant-scoped normalized payload, and require the winning command binding in the postcondition before reporting success.
- Treat revocation as immediate for new reserve/claim/heartbeat and prospective for already-running work. Scrub credentials atomically, fail unstarted reservations, retain leased artifact funds until terminal cancellation, preserve AUTHORIZATION_REVOKED as the terminal reason, and never delete append-only events, audits, nonce history, usage, evidence, or ledger entries.
- Sign control-plane to supplier-node calls over the exact body digest, timestamp, nonce, and job ID; reject stale, replayed, or body-mismatched requests.
- Persist supplier-node replay journal v2 with hashed identifiers, expiries, and gateway-token-keyed domain-separated HMAC commitments rather than raw request-body digests. Require a non-empty durable journal path and refuse startup rather than falling back to memory. Fsync claims before upstream execution; migrate live v1 records at startup; compact every five minutes, after 1,000 appends, at 8 MiB, or before the 16 MiB hard limit through an fsynced atomic replacement. Preserve the journal across restarts and make readiness plus future claims fail closed after corruption or any append/compaction failure. Allow only one active writer per gateway token until a shared atomic replay-claim store exists; a shared volume alone is not active-active HA.
- Keep public supplier-node readiness minimal; disclose Provider, model, data-class, and capacity inventory only through a signed one-time attestation and compare it with the pending authorization before activation.
- Require every billable supplier response to include canonical signed execution evidence binding the purchased Provider and exact model, actual upstream response model, input/output digests, provider request ID, usage, and completion time. Evidence mismatch fails without settlement.
- Keep supplier-node logs metadata-only and keep provider credentials, prompts, outputs, and native provider fields inside the node boundary.
- Keep Supplier Agent management loopback-only. Carry its one-time per-process launch secret only in a URL fragment, erase the fragment immediately, burn the secret after one same-origin bootstrap POST, and keep the resulting session only in an HttpOnly SameSite=Strict Cookie. Require same-origin writes and passphrase reauthentication for credential reveal, throttle failures, reject first-run setup overwrite, and encrypt local credentials with a user-held passphrase. Bind vault v2 to a domain-separated digest of the complete canonical validated profile as AES-GCM AAD; profile mutation and unbound vault v1 fail closed, with no trust-on-first-migration shortcut. Public tunnel setup is explicit and never changes host firewall or router state automatically.
- Keep large-file bytes out of JSON, D1, logs, checkpoints, and ordinary work directories. Use fixed resumable chunks in encrypted object storage, verify plaintext and ciphertext digests, and bind encryption AAD to tenant/artifact/part identity.
- Let Supplier Agents advertise file capability through short-lived signed outbound heartbeats. Queue only exact authorization/model/media/size matches; use expiring leases capped by a persisted absolute execution deadline, monotonic checkpoints, bounded attempts, queue timeouts, and fail-closed evidence settlement.
- Authenticate local checkpoint envelope version, task ID, createdAt, and expiresAt as AES-GCM AAD. Preserve the original expiry across rewrites within one attempt and cap lifetime at six hours. For a positive platform resume segment, require an exact authenticated checkpoint or return non-retryable ARTIFACT_CHECKPOINT_REQUIRED before downloading input or invoking a Provider. A segment-zero fresh attempt must delete the prior same-task checkpoint, pass no old state to runtime, and establish a new fixed lifetime. Perform bounded cleanup before every claim; remove expired/legacy/corrupt/temporary files, and if any discovered unsafe file cannot be deleted, return non-retryable CHECKPOINT_CLEANUP_FAILED without sending a claim. Apply the same fail-closed code when unsafe current-task state cannot be discarded during read. After accepted terminal completion, do not report task failure if checkpoint deletion fails; accepted completion and every other non-retryable terminal path must record a failed delete in the same process-local pending set, return CHECKPOINT_CLEANUP_FAILED, and retry before every later claim, blocking claims until success. On restart, the pending set is not persisted; the authenticated fixed expiry retains the six-hour validity bound, and pre-claim cleanup fails closed if the expired file cannot be removed.
- Reserve funds across all workload types in one atomic predicate, keep leased cancellation two-phase, and make completion consume a live bounded reservation in the same guarded batch as evidence and ledger postings.
- Bind every cancellation command ID to exactly one tenant-owned artifact task before changing state; expose `cancelling` as a non-terminal reservation-held projection and require v1 consumers to handle additive states conservatively.
- Coordinate object-store mutations with retryable indexed states and an independent deletion tombstone. Before artifact purge touches R2, use one D1 batch to enqueue deletion and mark the exact immutable generation `deleting`; never leave a queued delete permanently filtered by a `ready` row. Bound each invocation to one artifact and four generations and each queue round to four keys; return retryable 503 for incomplete explicit purge, and finalize `deleted` only when no generation metadata remains. Treat these bounds as resumable transitions, not proof of compatibility with a lower D1 ceiling: complete maintenance includes schema bootstrap and requires the Workers Paid 1,000-query-per-invocation quota in production. Repeat idempotent deletion beyond metadata removal, and do not discard the last deletion index while a byte deletion is unconfirmed.
- Treat artifact_tasks.content_purged_at as an output-expiry-or-purge marker, not standalone proof of full task purge. Require that marker plus empty instruction and output state, a purged/deleted associated artifact, and zero chunk generations; never hide the 48-hour input purge action merely because the 24-hour output expired. Once artifact/task full-purge state is true, every explicit retry must idempotently backfill missing completion audits using stable action/resource IDs and prevent duplicate tenant/action/resource events.
- Treat supplier/upstream plaintext visibility as an explicit product boundary. Require affirmative acknowledgement, keep customer content views buyer-only, default to strict minimal retention, and never claim execution-party confidentiality without attested confidential computing.
- Use independent credential, credential-lookup, replayable-content, artifact, and digest-commitment domains. Keep crypto format versions separate from persisted key ids. Gateway credential/lookup rings have at most eight total staged/readable keys across slot and compatibility sources. Bind slots to domain/key id with the manifest verifier, keep staged material outside operational namespaces, require applied monotonic generation/hash state, make lifecycle command IDs globally unique across domains/actions, and register canaries only through explicit lifecycle actions. The configured-readable-key baseline is allowed only by atomically consuming migration-proven one-way eligibility while complete durable history remains empty and only after an independent verifier matches; missing or consumed eligibility fails closed and it is never a repair path for a restored or used database. Validate persistent canaries and D1 references before runtime retirement, and disable the lookup legacy alias only through the strict opt-out flag after zero references. A verifier or canary never backs up a key; live zero references permit only removal from runtime, not deletion of the Sites copy or destruction of the final recovery copy while retained backups may still need it. Claim every lookup nonce namespace atomically, bound one Agent token to at most 100 projected valid authorizations, migrate all verified readable namespaces beyond that response cap, and never CAS-rewrap a ciphertext after another transition scrubbed it. Content/artifact/general commitment keys remain stable until their own key-id migrations exist.
- Preserve ledger, usage, evidence, and audit history during privacy purge; clear only replayable customer content and add purge timestamps/events.
- Drive expiry through both bounded traffic cleanup and a separately authenticated, pre-auth rate-limited scheduler. Validate that all four production cryptographic domains are distinct 32-byte values before retention mutation; export object-deletion health plus unclaimedExpiredArtifacts and pendingArtifactTombstones, each with an independent 24-hour breach count; fail scheduled monitoring on threshold or any breach; and treat cadence as a target rather than a hard deletion SLA.
- Ignore local .env, .dev.vars, and .wrangler state while retaining example templates; ignored secrets must still stay out of source, logs, prompts, fixtures, and build artifacts.
- Keep D1 upgrades backward compatible. Verify the authoritative 0000–0015 chain and all 24 tables against a real temporary legacy database, mirror additive columns, global uniqueness indexes, and fail-closed bootstrap provenance in the re-entrant runtime bootstrap, transactionally replace an obsolete CHECK when SQLite cannot alter it, and re-read schema before accepting a concurrent migration race.
- Do not add a second real strategy until `default` is solid.
